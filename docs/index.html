Stratum Design stage EMIT Critical Minerals L3

Stratum

A cost-function-driven mosaic engine for imaging spectroscopy, built to run in the cloud.

Status

There is no implementation. Everything here is specification and interface design, deliberately ahead of code. Names, contracts and file layouts are all still cheap to change — which is the point of writing them down first. “Stratum” is a working name.

The question this exists to answer

EMIT has built a mineral mosaic pipeline three times. Each one hard-codes a different answer to the same question:

The whole problem

When several observations cover the same patch of ground, which one wins?

V002 answers the most nadir look. EMIT-AMD answers whatever the temporal stacker decides afterwards. A third answer — prefer the observation that actually sees ground rather than vegetation — came out of the Colorado School of Mines tag-up and has no implementation anywhere.

Each answer arrived as a new pipeline. Stratum factors the question out instead. The framework owns the parts that never change — querying an index, regridding granules onto a common grid, orchestrating fan-out, caching, provenance — and exposes the parts that are genuinely science as versioned plugins. A science team iterates on a cost function; nobody rebuilds a pipeline.

The immediate driver is the EMIT Critical Minerals L3 mosaic, but nothing in the core is EMIT-specific. Instrument knowledge lives in a plugin package, stratum_emit.

Five stages

Only the middle three carry science. Everything else is machinery the framework should own once and never ask a scientist about again.

1

Plan

unit: run · Lambda

Manifest → index query → frozen candidate set → work list → budget gate. Freezing is what makes a run reproducible rather than merely repeatable.

2

Regrid PixelMask

unit: granule × tile · cached indefinitely

KD-tree nearest-neighbour from the granule’s loc array to the tile grid, producing a GLT. Pure geometry — it may not read a single science parameter.

3

Resolve Scorer

unit: tile × epoch × block

Apply the GLTs for this block, run the cost function, keep the winner. Writes the winning value, the score that won, and a contributing-observation count.

4

Reduce Reducer

unit: tile × block

Collapse epoch snapshots through time. Mode-through-time for Critical Minerals; a no-op here reproduces V002 exactly.

5

Publish OutputMapper

unit: tile · Lambda

Stitch blocks, write the data product and the rendered image, plus legend, STAC item and provenance record. Both artifacts, always.

Five plugin hooks

The first four decide which observation wins. The fifth decides what it looks like. They are separate hooks because their cost profiles differ by orders of magnitude, and collapsing them would force the cheapest decision to pay the price of the most expensive.

GranuleFilter1 · planµs, no IOWhich granules are candidates — dates, seasons, cloud, vintage
PixelMask2 · regridvectorizedWhich pixels are eligible — cloud, water, detector edges

The idea the whole design rests on

Separate geometry from science

Regridding is expensive and depends only on geometry. Scoring is cheap and changes hourly. V002 welds them together, so changing a selection criterion rebuilds every GLT. Splitting them and content-addressing the GLT turns “try a different cost function” from a full rebuild into a re-read.

Everything else follows from that split: the cache key table, the iteration story, the ability to run five competing scorers over one zone for the price of one, and the fact that stage 2 is forbidden from reading a scorer parameter. See Caching & iteration.

Two packages, one rule

stratumGrids, tiles, blocks, GLTs, class tables, caching, orchestration, provenanceTetracorder, minerals, spectral libraries, EMIT
stratum_emitL2B readers, detector-edge trims, mineral scorers, FRCOV, lumping tables—

The rule of thumb: if you find yourself writing “mineral” in a core module, it belongs in the plugin. This is not architectural fastidiousness — Colorado School of Mines is independently building the same thing for AVIRIS-5 and UAV imagery, so a second consumer already exists.
