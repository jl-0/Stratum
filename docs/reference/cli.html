stratum plan

stratum plan -m manifest.yaml [--out PATH] [--json]

Validates the manifest, queries the index, applies filters, resolves tiles and epochs, resolves every categorical layer's classes against each contributing granule's embedded table, and writes the run directory: manifest.merged.yaml, the frozen index.parquet, plan.json, work/{stage}.jsonl and report.md. Provisions nothing and reads no pixels — headers, variable lists and class tables only.

If the index under inputs.index_location does not exist and inputs.source is kind: local, the index is built first, so a laptop run is one command.

OptionEffectStatus
--out PATHThe run directory. Default {outputs.bucket}/runs/{run_id}, with outputs.bucket a path relative to the manifestbuilt
--jsonPrint run_id, run_dir, the counts and the budget verdict as JSONbuilt
--explain-filtersList the granules each filter removed, not just countsnot yet
--no-cache-probeSkip the cache probe; estimate as if nothing were cachednot yet

Exit codes: 0 valid and within budget, 2 valid but over budget (the plan is still written), 1 invalid. An empty selection — no granule survives the area, time and filters — is invalid, not an empty plan.

stratum run

stratum run -m manifest.yaml [--workers N] [--out PATH] [--dry-run]

Plans, then executes regrid → resolve → reduce → publish in a process pool on this machine, then writes the STAC collection and provenance.json and appends an execution table to report.md. Blocks until finished.

--tag KEY=VALUEExtra cost-allocation tags, repeatablenot yet

A run over budget stops before the first stage with exit 2 unless the manifest says on_exceed: warn. require_approval also stops it today, because stratum approve does not exist yet; the message says so.

A run is all-or-nothing: any failed item stops it after its stage completes, with the failures listed and recorded in work/{stage}.results.jsonl. Re-running the same manifest is cheap and safe: completed regrid, resolve and reduce items are cache hits and are skipped, so an interrupted run resumes. Publish is never a hit — products are written fresh under the run id.

stratum exec

stratum exec --plan <run-dir> --stage STAGE --index N

Executes a single work item from a run directory written by stratum plan and prints its outcome as one JSON line. This is the worker entrypoint every executor ultimately calls, and it is what a scheduler array task should invoke:

sbatch --array=0-724%64 --wrap \
  "stratum exec --plan $SCRATCH/run-01 --stage regrid --index \$SLURM_ARRAY_TASK_ID"
OptionEffectStatus

Useful directly when debugging: it reproduces exactly what a pool worker did, in your terminal, for one item.

stratum report

stratum report --run RUN [--root ROOT]

Prints report.md: the selection and what each filter removed, the builds consumed and the class-table fingerprint validated, the fan-out per stage, the budget verdict, and — once the run has executed — items, cache hits and seconds per stage.

--diff PREVIOUS and --format md|json are not yet. A large change in selected granules between runs of the same lineage usually means an upstream reprocessing or an index rebuild; until --diff exists, compare the two reports' selection sections.

stratum index

stratum index build  -m MANIFEST [--collection NAME]... [--since DATETIME]
stratum index query  --index PATH [--bbox W,S,E,N] [--start DATETIME] [--end DATETIME] [--collection NAME]... [--limit N]
stratum index verify -m MANIFEST
SubcommandDoesStatus
buildPopulates inputs.index_location (a directory; the file is granules.parquet) from inputs.source. A directory (kind: local) today; a catalogue later. Prints the row and granule countsbuilt local
queryAd-hoc query against a built index: a count and the first rows, with each granule's time, bbox and buildbuilt
verifyChecks asset URIs resolve and reports rows not seen since the last buildnot yet

--since passes through to the source as an updated-since filter — for a directory, file modification time — so a refresh is incremental and picks up granules that were re-delivered rather than newly acquired. See Building and refreshing the index.

This is the only command that talks to a catalogue

stratum plan, run and exec read a frozen index and never reach a live API. The one exception is convenience, not a query: plan builds a missing index from a local directory. That is what makes a run reproducible, and what keeps a large fan-out from rate-limiting an upstream service.

stratum plugins

stratum plugins list [--kind scorer|reducer|mask|filter|mapper|reader|source]
stratum plugins show REF [--kind KIND]

list enumerates what the current environment provides, by entry-point group. show resolves REF — an entry-point name or module:Class, trying every registry when --kind is omitted — and prints its class, module, version, and what it declares: capability, halo, required_roles, required_aux, space, outputs, collections. Useful for checking what a manifest must supply before you run it.

stratum validate

stratum validate -m manifest.yaml

Schema and cross-reference checks only: everything that can be checked without an index or a granule, reported as a list rather than the first failure. Prints ok and the run_id, or every problem and exit 1. Works offline and is fast enough for a pre-commit hook. Use plan when you want the checks that need real data.
