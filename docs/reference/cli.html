stratum plan

stratum plan -m manifest.yaml [-p PATCH]... [--json] [--out PATH]

Merges patches, validates the result, queries the index, applies filters, resolves tiles and epochs, probes the cache, and prints the fan-out with a cost estimate. Reads the index; provisions nothing; writes nothing unless --out is given.

OptionEffect
--out PATHWrite the resolved plan and frozen candidate set locally
--explain-filtersList the granules each filter removed, not just counts
--no-cache-probeSkip the cache probe; estimate as if nothing were cached

Exit codes: 0 valid and within budget, 2 valid but over budget, 1 invalid.

stratum run

stratum run -m manifest.yaml [-p PATCH]... [--executor NAME]
stratum run --from-provenance <uri>

Executes the pipeline. With no --executor it runs here, in a process pool, and blocks until finished.

OptionEffect
--executor NAMElocal (default), slurm, aws
--workers Nlocal: pool size. Default one per core.
--max-concurrent Nslurm/aws: cap on simultaneous work items, so one run cannot take the whole partition or account
--partition, --cpus-per-task, --mem, --timeslurm: passed through to sbatch
--wait / --no-waitBlock until the run finishes. Default: wait for local, do not wait for the others.
--from-provenance URIRe-run against a previous run's frozen index rather than re-querying
--dry-runEquivalent to plan
--no-cacheIgnore cache hits and rebuild everything
--no-cache-from STAGERebuild from this stage onward — glt, obs, snapshot, product
--tag KEY=VALUEExtra cost-allocation tags, repeatable

A run over budget with on_exceed: require_approval pauses before provisioning anything and waits for stratum approve.

Re-running the same manifest is cheap and safe: completed items are cache hits and are skipped, so an interrupted run resumes, and a run started on one executor can be finished on another.

stratum exec

stratum exec --plan <dir-or-uri> --stage STAGE --index N
stratum exec --plan <dir-or-uri> --stage STAGE --range A:B

Executes a single work item, or a contiguous slice, from a plan written by stratum plan --out. This is the worker entrypoint every executor ultimately calls, and it is what a scheduler array task should invoke:

sbatch --array=0-724%64 --wrap \
  "stratum exec --plan $SCRATCH/run-01 --stage regrid --index \$SLURM_ARRAY_TASK_ID"
OptionEffect
--stage STAGEregrid | resolve | reduce | publish
--index NZero-based item index within that stage's work list
--range A:BA contiguous slice, for when per-item scheduler overhead dominates
--forceRecompute even on a cache hit

Useful directly when debugging: it reproduces exactly what a Lambda or an array task did, on your machine, for one item.

stratum report

stratum report --run RUN_ID [--diff PREVIOUS_RUN_ID] [--format md|json]

Prints the run summary: granules considered and what each filter removed, cache hit rate by artifact type, failed blocks, cost against budget, and the vintage selected.

--diff compares against an earlier run of the same manifest lineage. A large change in selected granules usually means an upstream reprocessing or an index rebuild, and is worth seeing before it becomes a mystery in the product.

stratum approve / reject

stratum approve --run RUN_ID [--note TEXT]
stratum reject  --run RUN_ID [--note TEXT]

Releases or cancels a run paused at the budget gate. The note is recorded in provenance. Applies to any executor.

stratum render

stratum render --run RUN_ID --mapper REF [--params JSON] [--tile TILE]...

Re-renders published data blocks with a different mapper. Does not re-run the pipeline — the image is a pure function of the data product and the mapper, so this costs seconds. Writes a new image and legend alongside the existing ones; the data product is untouched.

stratum cache

stratum cache stats   [--run RUN_ID] [--type TYPE]
stratum cache explain KEY
stratum cache diff    KEY_A KEY_B
stratum cache gc      [--dry-run] [--older-than PERIOD]
SubcommandDoes
statsHit rate by artifact type, and what a rerun would cost
explainPrints the .inputs.json that produced a key, plus who wrote it and who references it
diffShows which input differs between two keys. The answer to "why did this miss?"
gcRemoves unreferenced entries past their lifecycle. Always --dry-run first.

Artifact types for --type: glt, obs, aux, snapshot, product, image.

stratum index

stratum index build  -m MANIFEST [--collection NAME] [--since DATE] [--until DATE]
stratum index verify -m MANIFEST [--collection NAME]
stratum index query  --index URI --bbox W,S,E,N --start DATE --end DATE
SubcommandDoes
buildPopulates or refreshes the GeoParquet index from inputs.source — a catalogue, or a directory. A periodic job, never part of a run.
verifyChecks asset URIs resolve and reports rows not seen since the last build — how an upstream reprocessing is detected
queryAd-hoc query against a built index, without writing a manifest

--since passes through to the source as an updated-since filter, so a refresh is incremental and picks up granules that were re-delivered rather than newly acquired. See Building and refreshing the index.

This is the only command that talks to a catalogue

stratum plan, run and exec read a frozen index and never reach a live API. That is what makes a run reproducible, and what keeps a large fan-out from rate-limiting an upstream service.

stratum plugins

stratum plugins list [--kind scorers|reducers|masks|filters|mappers|readers|sources]
stratum plugins show REF

list enumerates what the current image or environment provides. show prints a plugin's capability, declared roles and aux, halo, and outputs — useful for checking what a manifest must supply before you run it.

stratum validate

stratum validate -m manifest.yaml [-p PATCH]...

Schema and cross-reference checks only. Does not touch the index or any ancillary source, so it works offline and is fast enough for a pre-commit hook. Use plan when you want the checks that need real data.
