grid

grid:
  crs: EPSG:4326
  resolution: [0.000277778, -0.000277778]   # one arcsecond
  origin: [-180, -90]
  tile_size: 1.0
  block: 720
  max_distance: 0.00059      # regrid cutoff; default 1.5 x the grid diagonal
FieldTypeDefaultNotes
crsstring—Any CRS string GDAL accepts
resolution[float, float]—(x, y). y must be negative unless force_positive_y is set
origin[float, float]—Cell edges fall at origin + n × resolution
tile_sizefloat—In CRS units. The product unit. Need not be a whole number of cells; when it is not, tiles are cut on the cell lattice and differ by one cell
blockint512Cells per side. Cannot change output. Prefer a size that divides the tile, e.g. 720 for 3600 cells
max_distancefloat1.5 × grid diagonalBeyond it a regridded cell is marked interpolated. Enters the GLT cache key.
regrid_methodenumkdtreekdtree | warp_embedded — the latter warps the product's own lookup table, handed over by the reader. Enters the GLT cache key.
force_positive_yboolfalseDefeats the positive-y guard rail. Almost always the wrong thing to set.

Rejected at plan time: a positive y resolution without an explicit override, and resolution > 1 with a 4xxx EPSG. A tile whose cell count will not fit a worker produces a warning.

time

time:
  start: 2022-08-01
  end:   2026-07-31
  epoch: P1M
  deliver: P1Y             # shorthand for {every: P1Y, window: P1Y, align: exact}
  align: calendar          # optional - epoch generation, not window placement

Or the long form, when products should be delivered more often than the input window slides:

time:
  start: 2022-08-01
  end:   2026-07-31
  epoch: P1M
  deliver:
    every: P1M             # one product per month
    window: P13M           # each built from 13 months of epochs
    align: center
FieldTypeDefaultNotes
start, enddate—UTC. Bounds are half-open, [start, end).
epochISO 8601 period—The voting unit. One snapshot per epoch, regardless of how many observations fall in it.
deliverperiod, or objectepochA bare period is shorthand for {every: <period>, window: <same>, align: exact}
deliver.everyISO 8601 period—How often a product is emitted. Must be a whole multiple of epoch.
deliver.windowISO 8601 periodeverySpan of epochs feeding each product. Must be ≥ every and a whole multiple of epoch.
deliver.alignenumexactexact | center | trailing | leading — where the window sits relative to the delivery period
aligncalendarunsetAlign epoch generation to calendar boundaries instead of counting from start. Unrelated to deliver.align.

Windows are truncated at start and end, so the first and last products draw on fewer epochs. The count reaching each product appears in the n_epochs band and in the plan report.

Cost of overlapping windows

An epoch snapshot is cached per (tile, epoch, block, scorer); the delivery period is not in its key. Overlapping windows therefore re-run reduce only, and re-read resolve's snapshots.

granule_filter

An ordered list. Each entry is either a built-in predicate or a plugin reference.

granule_filter:
  - {build_version: "010635"}
  - {max_cloud_fraction: 0.5, on_missing: fail}
  - {max_solar_zenith: 70}
  - {month_in: [8, 9, 10, 11]}
  - {ref: my_package:CustomFilter, params: {...}}
PredicateEffect
build_versionFilters on the granule's software build, e.g. 010635. Optional — one collection spans many builds; the vintage guard is the class-table check below
product_versionThe granule's own product stamp from the file header, e.g. V001. Not a catalogue field; from CMR it equals the collection version
collection_versionPins the collection's version, e.g. 001. Constant within a collection, so it is not a vintage predicate
max_cloud_fractionUpper bound on reported cloud fraction
max_solar_zenithUpper bound on solar zenith angle
month_inRecurring seasonal window, as month numbers
day_nightDay or Night
on_missingfail (default) | reject | keep — per entry
Mixed vintages are refused

Stratum fingerprints every contributing granule's embedded class table. If they disagree, stratum plan fails unless allow_mixed_vintage: true is set at the top level with a documented reason. A run spanning a reprocessing boundary blends incompatible products into a plausible-looking result, and a build number does not catch it — the class table does.

pixel_mask

pixel_mask:
  - {ref: edge_trim, columns: 7}
  - {ref: l2a_standard, flags: [cloud, cirrus, water, spacecraft]}
  - {ref: soil_fraction, min_soil: 0.65}

Masks compose by conjunction — a pixel is eligible only if every entry admits it. Order does not affect the result. Any additional keys are passed to the plugin constructor.

snapshot

snapshot:
  name: cm-v1
  extends: []                              # names of schemas this one only appends to
  layers:
    mineral_1:
      kind: categorical
      source: mineral
      classes: "@ref:classes/cm-v1.yaml"
      aggregate: {method: vote, min_count: 3, ignore: [none], tie_break: highest_score}
    depth_1:
      kind: continuous
      source: mineral_depth
      aggregate: {method: inverse_variance, unc: depth_1_unc, conditional_on: mineral_1, spread: iqr}
    depth_1_unc:
      kind: continuous
      source: mineral_uncert
      aggregate: {method: none}

One per run, and constant across every epoch in it. It is what resolve writes and what reduce reads. See what the snapshot carries and specs/13-snapshot-schema.md.

Changing an aggregate re-runs reduce and publish only. Changing any other layer field re-runs resolve from cached geometry.

The classes file

name: cm-v1
match_on: [library, record, group]
unmapped: fail                    # fail | <class name>
classes:
  - {id: 1, name: goethite,
     members: [{library: sprlb06, record: 882,  group: 1},
               {library: splib06, record: 5736, group: 1}]}
  - {id: 3, name: pyrite,
     members: [{library: splib06, record: 2568, group: 1}]}

match_on names attribute columns from the role's class_table. Members are resolved per granule at plan time and an entry matching zero or multiple rows is an error. id is explicit and never reused; 0 is reserved for none, the "observed, nothing identified" class. Append new ids freely and list the previous schema in extends; renaming or renumbering is a new schema and rebuilds every epoch.

reducer

reducer:
  ref: my_package:ClassifyLast
  params: {...}

Optional. Omit it and the built-in reducer runs each layer's declared aggregate. Name a plugin only for logic the schema vocabulary cannot express; it receives the same snapshots and their schema.

plugins

plugins:
  wheel: s3://emit-l3/plugins/stratum_emit-0.4.2-py3-none-any.whl

Fetched to /tmp at worker cold start. The wheel URI and its content hash both enter the cache key and the provenance record. Omit the block to use whatever the container image ships; deployments may disable wheel fetching by policy for delivered products.

Composition

stratum plan -m base.yaml -p zones-pilot -p scorer-v3

Patches are ordered dict-merges applied before validation, so the merged document is what gets validated and hashed. Lists replace rather than append.

Validation

All of this fails at plan time, before compute is provisioned:

  • schema validity, with precise error locations;
  • named scorer, reducer, mapper and mask plugins resolve, with recordable versions;
  • every plugin's required_roles is present in inputs.roles;
  • every plugin's required_aux is declared in aux, and those sources exist and are readable;
  • kind and resampling agree for every aux source;
  • capability and halo are consistent with grid.block;
  • epoch divides deliver evenly;
  • the snapshot schema resolves: every layer source is a role or alias, every enumeration member matches exactly one class-table row per granule, and every class a colour table names exists in the enumeration;
  • contributing granules' class tables agree by fingerprint — the vintage check — or a remap is explicitly permitted;
  • every filter's on_missing policy is explicit;
  • every role's collection resolves to exactly one registered GranuleReader, and its var exists in that reader's variables;
  • every asset URI scheme is supported and credentials for it are obtainable now;
  • readers agree on space — an ortho-native role is not being asked for a regrid;
  • a collection the index holds under more than one collection_version is pinned with version:;
  • budget is present and finite.
