ObsWindow

The type a Scorer and a PixelMask receive. Two forms; the difference is one axis.

class ObsWindow:
    space: Literal["sensor", "block"]
    n: int                        # 1 streaming, N stacked
    block: BlockRef | None        # None in sensor space
    sensor_window: SensorWindow | None   # set in sensor space; carries row0/col0
    granule: GranuleRef | None    # None in stack mode
    granules: Sequence[GranuleRef]
    epoch: Epoch                  # the epoch being resolved
    sensor_shape: tuple[int, int] | None   # FULL (downtrack, crosstrack) of the variable; sensor space only
    band_attrs: Mapping[str, Mapping[str, Sequence]]   # per role/alias, what the reader reported per band

    def __getitem__(self, alias: str) -> np.ndarray:
        """Band by alias. (H, W) streaming, (N, H, W) stacked; (H, W, B) for a multi-band role."""

    @property
    def coords(self) -> Coords:
        """Cell centres: .x/.y in the grid CRS, .lon/.lat. Each (H, W)."""

    @property
    def valid(self) -> np.ndarray:
        """Bool. True = observed and unmasked. Same shape as a band."""

    @property
    def interpolated(self) -> np.ndarray:
        """Bool. True where the GLT reached beyond max_distance. Valid; penalise if you like."""

coords holds cell centres as four (H, W) arrays — x and y in the grid CRS, lon and lat always — so a scorer can do its own geometry against a declared vector source.

capability = "streaming"capability = "stack"
Calls to your methodOnce per granuleOnce per block
Band shape(H, W)(N, H, W)
granuleThe granuleNone
granulesOne elementAll N, ordered by acquisition time
MemoryO(block)O(block × N)

Ordering in stack mode is guaranteed ascending by datetime, so tie_break: earliest is well defined and a stack scorer can reason about sequence.

Address bands by alias, never index. Aliases are declared in the manifest per collection, so an alias-based plugin runs against a different instrument unchanged. An alias the manifest does not define is a plan-time error.

Two fields exist for sensor-space masks. sensor_shape is the full extent of the sensor array, not the window's: sensor_window says where your window starts, and only the full shape says where the detector ends, which is what an edge trim needs. band_attrs carries whatever the reader reported per band — names, wavelengths — so a mask can pick "Cloud flag" by name rather than by position. In sensor space bands are masked arrays; in block space they are plain arrays and valid is beside them.

AuxAccessor

class AuxAccessor:
    def raster(self, alias: str, *, date: datetime | None = None,
               epoch: Epoch | None = None) -> np.ndarray:
        """(H, W) on THIS block's grid. Warped, windowed, cached. epoch= for temporal: epoch sources."""

    def vector(self, alias: str) -> np.ndarray:
        """Rasterized to this block's grid."""

    def features(self, alias: str, *, margin: float = 0.0) -> Sequence[BaseGeometry]:
        """The source's geometries, clipped to this block plus margin, in the block CRS."""

    def distance(self, alias: str, *, cutoff: float | None = None) -> np.ndarray:
        """(H, W) distance from each cell centre to the nearest feature. Cached like a warp."""

    def table(self, alias: str) -> AuxTable:
        """.at(date) -> scalar. No gridding."""

    @property
    def granule_index(self) -> GranuleFrame: ...

Everything comes back windowed to your block, on your block's grid and CRS, already cached. You never reproject, resample or window anything.

Sources are addressed by manifest alias, never URI. An undeclared alias raises rather than falling back to opening a path — a read that is not in the cache key would silently go stale.

Two windows

Your plugin computes over window, which includes the halo. Stratum writes only core_window. You do not trim the halo yourself — the framework does it, which is why a halo cannot be applied inconsistently.

Grid alignment

observed EMIT's native ortho resolution is 0.000542232520256367. Setting a run grid to exactly that does not give you aligned cells, because granule origins differ — the nearest-neighbour regrid is required either way.

GranuleRef and GranuleFrame

@dataclass(frozen=True)
class GranuleRef:
    granule_id: str               # "001_20260825T151308_2623710_050"
    collection: str               # "EMITL2BMIN"
    datetime: datetime            # tz-aware UTC, acquisition start
    end_datetime: datetime
    bbox: tuple[float, float, float, float]
    assets: Mapping[str, str]     # asset name -> URI
    build_version: str            # "010635"  CMR SOFTWARE_BUILD_VERSION   [observed]
    product_version: str          # "V001"    file header; not in CMR      [observed]
    collection_version: str       # "001"     the collection's version
    cloud_fraction: float | None
    day_night: str | None       # "Day"        [observed]
    attributes: Mapping[str, str] # the source's remaining fields, verbatim
    checksums: Mapping[str, str]  # asset name -> catalogue checksum; empty for a directory source

GranuleFrame is the plural form — a dataframe with these as columns, which is what GranuleFilter.keep() receives. Operate on it vectorized.

Three version fields, deliberately. build_version is a property of this granule and moves often — one collection already holds eight of them. product_version is the file's own stamp and in practice tracks the collection. collection_version is identical for every granule in a collection. None of the three is the vintage check; that is the class table's fingerprint, because a class shift is what a reprocessing changes. All three are carried so a run can report exactly what it read.

cloud_fraction is nullable and the nullness is meaningful: None means the granule reports no cloud metadata, which is a different situation from reporting a high value. Filters take an explicit on_missing policy rather than guessing.

    """Reducer input. Epoch-major."""
    schema: SnapshotSchema
    epochs: Sequence[Epoch]                           # ordered, ascending
    def __getitem__(self, layer: str) -> np.ndarray:  # (n_epochs, H, W) or (n_epochs, H, W, B)
    @property
    def valid(self) -> np.ndarray:                    # (n_epochs, H, W) bool
    @property

    """OutputMapper input. Finished bands for one tile."""
    def __getitem__(self, band: str) -> np.ndarray:   # (H, W)
    specs: Sequence[BandSpec]

snaps[...] resolves any layer the SnapshotSchema declares, plus score and valid. A categorical layer holds product ids from its enumeration, never a raw class. Every snapshot in a run shares one schema, and its layers_hash is in every snapshot's cache key. Scorer-computed layers are planned, not in v1. See what the snapshot carries.

Check snaps.valid rather than testing values against a sentinel. An epoch with no observation over a pixel must not count toward an agreement fraction, and valid is how you tell.

snaps.score carries the score that won each cell in each epoch, so an aggregation can weight by confidence instead of treating every epoch equally.

lumping is why re-lumping an enumeration — changing which raw classes a product id gathers, with every id and name unchanged — still invalidates snapshots: the members decide the values a snapshot holds. BandSpec.bands exists because the schema alone cannot know the width of a bands: None source; the planner records it from the reader and the reducer's band_counts() can produce it from a real stack.

GLT

You only touch this if you work with geometry directly; ordinary plugins never see one.

@dataclass
class GLT:
    data: np.ndarray              # (H, W, 3) int32
    grid: GridDef
    tile: TileRef
    granule: GranuleRef               # one GLT per granule; band 3 is always 1
    score: np.ndarray | None      # (H, W) float32 - the winning score
BandContains
1GLT X — source column, 1-based
2GLT Y — source row, 1-based
3File Index — always 1, kept so existing tooling opens the file. granule_id is in the metadata

0 is nodata. A negative value in bands 1–2 marks an interpolated cell — one whose nearest source pixel lay beyond max_distance. Take the absolute value to index, and check the sign when you care whether the data was reached for.

score is None for every GLT Stratum writes: a per-granule GLT is built before any selection, so there is no winning score to carry. The score that won each cell is in the epoch snapshot (snaps.score) instead. The field exists so a fused GLT written by another tool can carry the score it has.

EmbeddedGLT

@dataclass
class EmbeddedGLT:
    data: np.ndarray              # (H, W, 3) int32: GLT X, GLT Y, hit
    transform: Affine             # the product's own ortho grid
    crs: str                      # WKT, as the file carries it

What GranuleReader.glt() returns: the lookup table a product ships on its own ortho grid, with its own georeferencing. It is not on any run grid — no grid, tile or granule — and is what the warp_embedded regrid method (not yet built) warps onto a tile. Band 3 is 1 wherever bands 1–2 are set, mirroring the file-index band of a Stratum GLT.

ClassTable

@dataclass(frozen=True)
class ClassTable:
    key: str                              # column whose values appear in pixels
    entries: pa.Table                     # key + arbitrary attribute columns
    source: str                           # provenance: URI + path, or file
    def attrs(self) -> Sequence[str]: ...
    def fingerprint(self) -> str: ...     # content hash; enters cache keys

Where a table lives is declared per role in the manifest — see class_table. Prefer source: embedded: the table travels with the data it describes and cannot drift from it.

Key columns are positional, so the same integer can mean different things in granules of different vintages. Refer to classes by attribute wherever you name one, and Stratum resolves attributes to integers per granule at plan time. It also fingerprints every contributing table and fails if they disagree, unless a cross-vintage remap is explicitly permitted. Product ids run 1…65534; 0 is reserved for none and 65535 is the delivered nodata.

Products publish their own class table: after lumping, a mosaic's classes are not its inputs' classes.
