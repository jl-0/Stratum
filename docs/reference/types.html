Core types

The concrete objects that cross every interface. Every other page names these; this one defines them.

Generated later

Field lists here are hand-written and will be extracted from the source once stratum exists — a field list maintained in two places is a field list that drifts. What stays hand-written is the narrative: why a type is shaped the way it is, and which observed constraint forced it. That is the part a generator cannot produce.

Grounding

Anything marked observed was read out of a real delivered granule — EMIT_L2B_MIN_001_20260825T151308_2623710_050.nc, product version V001, software_build_version 010635. Everything else is a design decision. Keeping that distinction visible is what separates a spec from a plausible story.

Grid, tile, block

@dataclass(frozen=True)
class GridDef:
    crs: str                          # "EPSG:4326"
    resolution: tuple[float, float]   # (x, y); y negative
    origin: tuple[float, float]       # cell edges at origin + n*res
    tile_size: float
    block: int = 512

    @property
    def id(self) -> str: ...      # short stable hash; part of every cache key

@dataclass(frozen=True)
class TileRef:
    grid: GridDef
    tx: int
    ty: int
    @property
    def bounds(self) -> tuple[float, float, float, float]: ...
    @property
    def shape(self) -> tuple[int, int]: ...
    @property
    def name(self) -> str: ...    # "{grid.id}/{tx}_{ty}"

@dataclass(frozen=True)
class BlockRef:
    tile: TileRef
    bx: int
    by: int
    halo: int = 0
    @property
    def window(self) -> Window: ...        # with halo
    @property
    def core_window(self) -> Window: ...   # without - what gets written
    @property
    def transform(self) -> Affine: ...
Two windows, deliberately

Plugins compute over window; the framework writes only core_window. That is the whole halo mechanism, and keeping it in the type rather than in caller code is what stops a plugin author getting it wrong.

Tiles are named by grid indices — emit30/-111_32 — so a name is a position rather than a label. AMD names directories 32_33_-111_-110, which is readable but redundant with the grid and awkward to sort; bounds belong in metadata, not in the identifier.

observed A trap in grid alignment

EMIT’s native ortho resolution is 0.000542232520256367, and V002’s 0.00055 is a rounding of it. But a run grid at exactly the native resolution is not automatically aligned — origins are per-granule — so the KD-tree path is still required regardless.

Granules

@dataclass(frozen=True)
class GranuleRef:
    granule_id: str               # "001_20260825T151308_2623710_050"
    collection: str               # "EMITL2BMIN"
    datetime: datetime            # tz-aware UTC
    end_datetime: datetime
    bbox: tuple[float, float, float, float]
    assets: Mapping[str, str]     # role -> URI
    build_version: str            # "010635"          [observed]
    product_version: str          # "V001"            [observed]
    cloud_fraction: float | None  # None is meaningful
    day_night: str | None       # "Day"             [observed]

GranuleFrame is the plural form — a dataframe with these as columns, which is what GranuleFilter.keep() receives.

cloud_fraction being nullable is not an oversight: nullness is meaningful, and conflating “no cloud metadata” with “too cloudy” is the exact silent-drop bug this design exists partly to fix.

observed Vintage identifiers exist

The granule carries software_build_version (010635), software_delivery_version and product_version (V001) as global attributes, and its history names tetracorder5.27c.cmds — confirming the file predates the Tetracorder 6 reprocessing. So the identifier is unambiguous in the file. Still open: whether CMR exposes it before download, which decides whether vintage filtering can be an index predicate.

AuxAccessor

class AuxAccessor:
    def raster(self, alias: str, *, date: datetime | None = None) -> np.ndarray:
        """(H, W) on THIS block's grid. Warped, windowed, cached."""

    def vector(self, alias: str) -> np.ndarray:
        """Rasterized to this block's grid."""

    def table(self, alias: str) -> AuxTable:
        """.at(date) -> scalar. No gridding."""

    @property
    def granule_index(self) -> GranuleFrame: ...
The block grid is the contract

Everything AuxAccessor returns is already windowed to the block, already on the block’s exact grid and CRS, and already cached. A scorer never does geometry, never sees a CRS, never resamples anything. If a plugin author has to think about projections, the framework has failed — and readable cost functions are the entire point.

Sources are addressed by manifest alias, never URI. An undeclared alias raises; it does not fall back to opening a path. That is what makes the declaration requirement enforceable rather than aspirational, and it is what keeps cache keys honest.

Resampling is declared, never defaulted. Bilinear-interpolating a landcover class and nearest-neighbouring a DEM are both wrong and neither raises an error — they quietly produce a cost surface nobody can explain later. A categorical source with a continuous resampling method is a plan-time error.

GLT

@dataclass
class GLT:
    data: np.ndarray              # (H, W, 3) int32
    grid: GridDef
    tile: TileRef
    granules: Sequence[GranuleRef]    # File Index is 1-based into this
    score: np.ndarray | None      # (H, W) float32 - the winning score

Bands are (GLT X, GLT Y, File Index), 1-based, 0 = nodata, negatives = interpolated. The format matches the existing convention so artifacts interoperate.

score is typed optional only because a GLT read back from a V002-era file will not have one. In practice it is required — persisting it is what makes “why did this pixel win?” answerable from the artifact.

observed The granule ships its own GLT

location/glt_x and location/glt_y (int32, _FillValue = 0, observed range 1–1242) map the granule’s own ortho grid (2363 × 2309) back to sensor space. This is not our tile grid — the origin is per-granule — so it cannot substitute for the KD-tree regrid. It is worth knowing for two reasons: it is what load_data(..., load_glt=True) returns, and it is a ready-made fixture for testing GLT application without building one.

Snapshots, bands, outputs

@dataclass(frozen=True)
class BandSpec:
    name: str
    dtype: str
    description: str
    units: str = "unitless"
    nodata: float | int | None = None

class SnapshotStack:
    """Reducer input. Epoch-major."""
    epochs: Sequence[Epoch]                           # ordered, ascending
    def __getitem__(self, band: str) -> np.ndarray:   # (n_epochs, H, W)
    @property
    def valid(self) -> np.ndarray:                    # (n_epochs, H, W) bool
    @property
    def score(self) -> np.ndarray:                    # (n_epochs, H, W) float32

class BandStack:
    """OutputMapper input. Finished bands for one tile."""
    def __getitem__(self, band: str) -> np.ndarray:   # (H, W)
    specs: Sequence[BandSpec]

SnapshotStack.valid is what keeps min_count honest: an epoch with no observation over a pixel must not count toward agreement. Exposing score lets a reducer weight by confidence rather than treating every epoch equally — an open question, left available in the type so it stays cheap to answer later rather than awkward.

ClassTable

Some bands are categorical: their integer values index a table of classes. The framework needs a generic way to carry that table around, and it must not know what the classes mean.

@dataclass(frozen=True)
class ClassTable:
    key: str                              # column whose values appear in pixels
    entries: pa.Table                     # key + arbitrary attribute columns
    source: str                           # provenance: URI + path, or file
    def attrs(self) -> Sequence[str]: ...
    def fingerprint(self) -> str: ...     # content hash; enters cache keys

Where to find it is configuration, declared per role, so the framework never hard-codes a path and products that do not embed a table are equally expressible:

inputs:
  roles:
    mineral:
      collection: EMITL2BMIN
      var: group_1_mineral_id
      class_table:
        source: embedded          # embedded | file
        path: /mineral_metadata   # group within the product
        key: index                # column matching pixel values
        attributes: [name, record, library, group, url]
Self-describing products are the good case

observed The L2B granule embeds its class table at /mineral_metadata — 294 entries. This is the arrangement to prefer wherever a product offers it, because the authority travels with the data: no external CSV to drift, no vintage to pin by hand, and no way for the table to disagree with the pixels it describes. A reader that pulls the table out of the granule it is currently processing is correct by construction.

The residual problem, and why it is tractable

A mosaic spans many granules, and their class tables must agree — a pixel value of 15 has to mean the same thing in every granule contributing to a cell, or the reduction is nonsense.

observed index is 1…294, contiguous and positional. v6.00a6.csv has 312 entries. So the index space genuinely does differ between vintages, and during the reprocessing window a run can span both.

The embedded table does not make that go away. What it does is make it detectable and mechanically solvable, where an external table would have made it silent:

  1. Fingerprint every granule’s table at plan time.
  2. All identical → the common case. Proceed; record the fingerprint in provenance.
  3. They differ → the run spans vintages. Either fail loudly, or remap through the attribute columns, which carry enough identity to compute the correspondence. Measured on the delivered file, (library, record, group) resolves 292 of 294 entries — so a remap is computable, with a short list of genuine ambiguities surfaced for a human rather than guessed.

That check is generic: it is “do these class tables agree”, not “do these minerals agree”, which is why it belongs in the core.

And output products carry their own table. A mosaic’s classes are its own — post-lumping, they are not the input classes — so stage 5 publishes a ClassTable alongside the product, which is the legend requirement arrived at from the other direction.

Observed oddities

Recorded so nobody re-derives them.

  • bands = 4 is declared but unused by any root variable in the L2B MIN file. Presumably for the MINUNCERT companion. Do not assume it means four spectral bands.
  • Only two mineral groups exist (group_1_*, group_2_*), matching AMD’s config.
  • The delivered GLT contains no negative values, so the interpolated-cell convention is Stratum/SpectralUtil-internal, not something read from granules.
  • Global attributes carry geotransform and spatial_ref (WKT) directly, so granule-ortho georeferencing needs no reconstruction.
  • Conventions are CF-1.13 / NCEI_NetCDF_Swath_Template_v2.0 — worth matching in our own NetCDF output.
