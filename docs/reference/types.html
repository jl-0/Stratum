On the observed marker

Values marked this way are what a delivered EMIT L2B granule actually contains (V001, build 010635), not defaults Stratum imposes. They are here so you know what to expect from real data.

ObsWindow

The type a Scorer and a PixelMask receive. Two forms; the difference is one axis.

class ObsWindow:
    space: Literal["sensor", "block"]
    n: int                        # 1 streaming, N stacked
    block: BlockRef | None        # None in sensor space
    granule: GranuleRef | None    # None in stack mode
    granules: Sequence[GranuleRef]

    def __getitem__(self, alias: str) -> np.ndarray:
        """Band by alias. (H, W) streaming, (N, H, W) stacked."""

    @property
    def valid(self) -> np.ndarray:
        """Bool. True = observed and unmasked. Same shape as a band."""

Ordering in stack mode is guaranteed ascending by datetime, so tie_break: earliest is well defined and a stack scorer can reason about sequence.

Address bands by alias, never index. Aliases are declared in the manifest per collection, so an alias-based plugin runs against a different instrument unchanged. An alias the manifest does not define is a plan-time error.

AuxAccessor

class AuxAccessor:
    def raster(self, alias: str, *, date: datetime | None = None) -> np.ndarray:
        """(H, W) on THIS block's grid. Warped, windowed, cached."""

    def vector(self, alias: str) -> np.ndarray:
        """Rasterized to this block's grid."""

    def table(self, alias: str) -> AuxTable:
        """.at(date) -> scalar. No gridding."""

    @property
    def granule_index(self) -> GranuleFrame: ...

Everything comes back windowed to your block, on your block's grid and CRS, already cached. You never reproject, resample or window anything.

Sources are addressed by manifest alias, never URI. An undeclared alias raises rather than falling back to opening a path — a read that is not in the cache key would silently go stale.

GridDef, TileRef, BlockRef

@dataclass(frozen=True)
class GridDef:
    crs: str                          # "EPSG:4326"
    resolution: tuple[float, float]   # (x, y); y negative
    origin: tuple[float, float]       # cell edges at origin + n*res
    tile_size: float
    block: int = 512

    @property
    def id(self) -> str: ...      # short stable hash; part of every cache key

@dataclass(frozen=True)
class TileRef:
    grid: GridDef
    tx: int
    ty: int
    @property
    def bounds(self) -> tuple[float, float, float, float]: ...
    @property
    def shape(self) -> tuple[int, int]: ...
    @property
    def name(self) -> str: ...    # "{grid.id}/{tx}_{ty}"

@dataclass(frozen=True)
class BlockRef:
    tile: TileRef
    bx: int
    by: int
    halo: int = 0
    @property
    def window(self) -> Window: ...        # with halo
    @property
    def core_window(self) -> Window: ...   # without - what gets written
    @property
    def transform(self) -> Affine: ...
Two windows

Your plugin computes over window, which includes the halo. Stratum writes only core_window. You do not trim the halo yourself — the framework does it, which is why a halo cannot be applied inconsistently.

Grid alignment

observed EMIT's native ortho resolution is 0.000542232520256367. Setting a run grid to exactly that does not give you aligned cells, because granule origins differ — the nearest-neighbour regrid is required either way.

GranuleRef and GranuleFrame

@dataclass(frozen=True)
class GranuleRef:
    granule_id: str               # "001_20260825T151308_2623710_050"
    collection: str               # "EMITL2BMIN"
    datetime: datetime            # tz-aware UTC, acquisition start
    end_datetime: datetime
    bbox: tuple[float, float, float, float]
    assets: Mapping[str, str]     # role -> URI
    build_version: str            # "010635"     [observed]
    product_version: str          # "V001"       [observed]
    cloud_fraction: float | None
    day_night: str | None       # "Day"        [observed]

GranuleFrame is the plural form — a dataframe with these as columns, which is what GranuleFilter.keep() receives. Operate on it vectorized.

cloud_fraction is nullable and the nullness is meaningful: None means the granule reports no cloud metadata, which is a different situation from reporting a high value. Filters take an explicit on_missing policy rather than guessing.

SnapshotStack, BandStack, BandSpec

@dataclass(frozen=True)
class BandSpec:
    name: str
    dtype: str
    description: str
    units: str = "unitless"
    nodata: float | int | None = None

class SnapshotStack:
    """Reducer input. Epoch-major."""
    epochs: Sequence[Epoch]                           # ordered, ascending
    def __getitem__(self, band: str) -> np.ndarray:   # (n_epochs, H, W)
    @property
    def valid(self) -> np.ndarray:                    # (n_epochs, H, W) bool
    @property
    def score(self) -> np.ndarray:                    # (n_epochs, H, W) float32

class BandStack:
    """OutputMapper input. Finished bands for one tile."""
    def __getitem__(self, band: str) -> np.ndarray:   # (H, W)
    specs: Sequence[BandSpec]

snaps[...] resolves any band the Scorer named in carry, plus score and valid. A snapshot is an internal artifact rather than a rendered product, so it can be as wide as the reduction needs. Scorer-computed bands are planned, not in v1. See what the snapshot carries.

Check snaps.valid rather than testing values against a sentinel. An epoch with no observation over a pixel must not count toward an agreement fraction, and valid is how you tell.

snaps.score carries the score that won each cell in each epoch, so a reducer can weight by confidence instead of treating every epoch equally.

GLT

You only touch this if you work with geometry directly; ordinary plugins never see one.

@dataclass
class GLT:
    data: np.ndarray              # (H, W, 3) int32
    grid: GridDef
    tile: TileRef
    granules: Sequence[GranuleRef]    # File Index is 1-based into this
    score: np.ndarray | None      # (H, W) float32 - the winning score
BandContains
1GLT X — source column, 1-based
2GLT Y — source row, 1-based
3File Index — which granule, 1-based into granules

0 is nodata. A negative value in bands 1–2 marks an interpolated cell — one whose nearest source pixel lay beyond max_distance. Take the absolute value to index, and check the sign when you care whether the data was reached for.

score is typed optional only because a GLT written by an older tool will not carry one. Stratum always writes it.

ClassTable

@dataclass(frozen=True)
class ClassTable:
    key: str                              # column whose values appear in pixels
    entries: pa.Table                     # key + arbitrary attribute columns
    source: str                           # provenance: URI + path, or file
    def attrs(self) -> Sequence[str]: ...
    def fingerprint(self) -> str: ...     # content hash; enters cache keys

Where a table lives is declared per role in the manifest — see class_table. Prefer source: embedded: the table travels with the data it describes and cannot drift from it.

Key columns are positional, so the same integer can mean different things in granules of different vintages. Refer to classes by attribute wherever you name one, and Stratum resolves attributes to integers per granule at plan time. It also fingerprints every contributing table and fails if they disagree, unless a cross-vintage remap is explicitly permitted.

Products publish their own class table: after lumping, a mosaic's classes are not its inputs' classes.
