Stratum Design stage EMIT Critical Minerals L3

Plugin contracts

Five hooks. The first four decide which observation wins; the fifth decides what it looks like.

Generated later

The Protocol definitions on this page are hand-written for now. Once stratum exists they will be extracted from the source so signatures cannot drift from the implementation. The prose and the worked examples stay hand-written — those are design, not API surface.

Why five and not one

The decisions a mosaic makes have wildly different cost profiles and run at different stages. Collapsing them into one interface forces the cheapest to pay the price of the most expensive.

HookStageGranularityCostStatus
GranuleFilter1 planper granuleµs, no IOlocked
PixelMask2 regridgranule × blockvectorizedlocked
Scorer3 resolvetile × epoch × blockvectorizedlocked
Reducer4 reducetile × blockN = #epochsone open field
OutputMapper5 publishper tilepresentationlocked

Two consequences worth stating outright:

  • Rejecting early is free. A GranuleFilter prunes before a byte is read. The same predicate applied at pixel level costs a download, a regrid, and a scoring pass.
  • Masking is not ranking. PixelMask returns a boolean; it never expresses preference. Mixing the two is how “this pixel is unusable” quietly becomes “this pixel is merely worse”.

GranuleFilter

class GranuleFilter(Protocol):
    def keep(self, granules: GranuleFrame) -> BoolArray:
        """Vectorized over the whole candidate frame. True = keep."""

    def describe(self) -> str:
        """One line for the run report, e.g. 'cloud_fraction <= 0.5'."""

Filters are vectorized over the index as a dataframe and never see individual granules.

Temporal range is a filter, and it is not just start/end

“Limit the temporal range” belongs here rather than in pipeline code. EMIT-AMD applies none at all and hands every observation ever acquired to the stacker; for a versioned annual product the range must be declared, pinned and recorded.

FilterExpresses
start / endAn absolute interval — the mission window, or one delivery year
month_in: [8, 9, 10, 11]A recurring seasonal window

The seasonal form is the one that is easy to miss. The useful window recurs annually — taking August-to-November scenes over the Western US avoids peak vegetation without discarding whole years — and a start/end range cannot express that. Building it out of many disjoint intervals is miserable.

Exclusions must be reported by reason

Requirement

The filter chain records, per filter, how many granules it removed and why, into the run report. Missing metadata is an explicit policy in the manifest — on_missing: reject | keep | fail — never the accidental result of a truth test. Default is fail at plan time, loudly, while it is cheap to fix.

The precedent is V002’s cloud filter, where a granule whose record lacks the key is dropped silently, indistinguishable from “too cloudy”. A run that quietly discarded 812 granules should say so where someone will see it.

Vintage pinning is mandatory

Reprocessing of the entire catalog begins ~September 2026, runs ~75 days, and regenerates every mineral map against Tetracorder 6 — and the mineral classes shift. For that window the archive is mixed-vintage, and an unpinned run will silently blend two incompatible products into a result that looks entirely plausible.

build_version is therefore a required filter, and plan-time validation fails if a run’s frozen index spans more than one vintage unless the manifest explicitly opts in.

PixelMask

Runs during regrid, so masked pixels never enter the observation stack. Masks compose by conjunction: a pixel is eligible only if every mask in the chain admits it.

class PixelMask(Protocol):
    space: Literal["map", "sensor"] = "map"
    required_roles: tuple[str, ...] = ()

    def valid(self, obs: ObsWindow, aux: AuxAccessor) -> BoolArray:
        """(H, W) bool. True = usable.
        space="map"    -> obs is on the block grid, post-GLT.
        space="sensor" -> obs is in raw (downtrack, crosstrack) geometry, pre-GLT.
        """

The space field exists because some masks are naturally expressed in map geometry (this location is water) and some in sensor geometry (this detector column is unreliable). The second cannot be expressed after regridding has discarded the source column, so sensor-space masks are applied to the raw array before the GLT is built.

A trick we are not using

A column mask could be evaluated in map space by thresholding GLT band 1, which holds the source column. But it fails for any mask needing raw values rather than raw indices. Applying them in raw space is honest and simpler.

Built-in EMIT masks

Instrument knowledge belongs in stratum_emit, not in user config.

No along-track trimming

EMIT is a push-broom collecting one continuous strip. Granule boundaries in the along-track direction are a download convenience with no physical meaning, so top and bottom edges are sound. Trimming them would discard good data.

Scorer — the cost function proper

class Scorer(Protocol):
    capability: Literal["streaming", "stack", "tile"]
    halo: int = 0
    required_roles: tuple[str, ...] = ()
    required_aux:   tuple[str, ...] = ()

    def score(self, obs: ObsWindow, aux: AuxAccessor) -> FloatArray:
        """Higher wins. NaN marks a cell this observation may not occupy."""

Execution modes

capability is a promise about what the scorer needs to see, and it determines both memory behaviour and where the work runs.

CapabilityCalledBand shapeMemoryExample
streamingonce per granule(H, W)O(block)min view zenith
stackonce with all observations(N, H, W)O(block × N)median, consensus
tileonce per whole tile(N, H, W)O(tile × N)segmentation

streaming is the V002 shape: a running best-score array updated granule by granule, with memory independent of how many observations exist. That property is worth preserving and the framework keeps it available. stack is the AMD shape: nothing is discarded, so any reduction is expressible — it is what mode-through-time needs, and block decomposition is what keeps it affordable. tile is the escape hatch; it routes to Batch and gives up block parallelism.

In stack mode observations are ordered by datetime, guaranteed, so that tie_break: earliest is meaningful and stack-mode scorers can reason about sequence.

Bands by alias, never by index

obs["view_zenith"]        # (H, W) float, this block only
obs.granule.datetime      # metadata
obs.grid                  # this block's transform and CRS
obs.n                     # 1 when streaming, N when stacked

The manifest maps aliases to (role, band) per collection, so the same scorer works across instruments — which matters now that Mines makes multi-instrument a live requirement. Requesting an alias the manifest does not define is an error at plan time, via required_roles, not at runtime in 4,000 workers.

Worked examples

class MinViewZenith:
    """V002 parity: the most nadir look wins."""
    capability = "streaming"
    required_roles = ("geometry",)

    def score(self, obs, aux):
        return -obs["view_zenith"]
class PreferBareEarth:
    """Prefer the observation that actually sees ground.

    Given several observations of a pixel, most of which are vegetation,
    take the one that isn't. Soil fraction comes from the already-
    orthorectified L2B FRCOV product, so this costs nothing to regrid.
    """
    capability = "streaming"
    required_roles = ("frcov",)

    def __init__(self, min_soil=0.80, hard_floor=0.65):
        self.min_soil, self.hard_floor = min_soil, hard_floor

    def score(self, obs, aux):
        soil = obs["soil_fraction"]
        s = soil.copy()
        s[soil < self.hard_floor] = np.nan     # unrecoverable; V002 used 0.65
        return s

The two thresholds are deliberate. hard_floor=0.65 is V002’s cutoff, chosen because grain-size retrieval falls apart below it; min_soil=0.80 is the higher bar recommended for mosaicking. Keeping them separate lets the scorer rank between 0.65 and 0.80 rather than discarding that range outright — which is the “don’t destroy information” principle applied at the smallest possible scale.

Caveat to carry

The current FRCOV is reportedly NPV-false-positive-prone — it reads some bare soil as non-photosynthetic vegetation — so this scorer is conservative in a way that will improve when FRCOV does.

The score band is persisted

Requirement

Stage 3 writes the winning score alongside the winning value. For a product whose premise is defensible selection, “why did this pixel win?” must be answerable from the artifact. The existing regrid computes the criteria array and discards it.

Reducer

class Reducer(Protocol):
    outputs: tuple[BandSpec, ...]
    halo: int = 0

    def reduce(self, snaps: SnapshotStack, aux: AuxAccessor) -> dict[str, Array]:
        """snaps[name] is (n_epochs, H, W). One array per declared output."""

Outputs are declared up front so the COG/NetCDF schema, the STAC item and the OutputMapper contract can all be derived without running anything.

class ModeThroughTime:
    outputs = (
        BandSpec("mineral_id",   "uint16",  "most frequent class across epochs"),
        BandSpec("agreement",    "float32", "modal count / valid epochs"),
        BandSpec("n_epochs",     "uint8",   "epochs contributing"),
        BandSpec("runner_up_id", "uint16",  "second most frequent class"),
    )

min_countSuppress pixels whose modal class has too few votesstack.mincount: 3

Reduce continuously where possible

Tetracorder’s output is already binarized, so information has been lost before we see it. That argues for reducing the continuous quantities — band depth, fit, uncertainty — and classifying at the end, rather than voting over labels that have already thrown information away.

Two consequences. ModeThroughTime over labels stays as the baseline, because it is what AMD does and what we can validate against — but it should not be the only reducer we ship. And a ConsensusDepth-style reducer that aggregates band depths per candidate mineral and classifies the aggregate is the more principled version, which the design must not make awkward. That is why Reducer receives the full snapshot stack rather than a single band; both are the same contract, differing only in which bands the Scorer was asked to carry forward.

Why this is pluggable at all

The reason, stated plainly

Temporal stability is an open geological hypothesis, and the right assumption depends on the question being asked. If you are making a base map you probably do not care much; if you are looking at sand dunes you care a lot. No single temporal algorithm is correct for both — which is precisely why the reducer is a plugin and not a setting.

And the honesty check: passing a single epoch through unchanged gives V002 semantics exactly. The old behaviour must be a configuration of the new system, not a special case beside it.

OutputMapper

class OutputMapper(Protocol):
    outputs: tuple[ImageSpec, ...]

    def render(self, bands: BandStack, aux: AuxAccessor) -> RGBAArray:
        """(H, W, 4) uint8. Free to consult any finished band, and aux."""

    def legend(self) -> Legend:
        """Class table or ramp stops. Sidecar + STAC. Not optional."""
The rule

The mapper is a presentation layer over a data product that still ships. Stage 5 writes both, from the same block, in the same run.

The failure mode being avoided is concrete. AMD’s delivered rasters are RGBA with the class already rendered, and the colormap lives only in a cluster config. Nothing downstream can restyle; nothing can recount; and the counts product was dropped entirely because the coastal mask burns band 4 — alpha — which a single-band raster does not have. A whole product was lost to an RGBA assumption baked into a pipeline.

Most mappings are a lookup table or a ramp and must never require code, so categorical, continuous, threshold and composite mappers are configured in the manifest and validated at plan time. on_unmapped: fail is the default deliberately: a class that appears in the data but not the colormap is a real error, and silently rendering it grey is how a mineral goes missing from a map without anyone noticing.

One generalization worth calling out — confidence-driven alpha. Deriving opacity from the agreement band means low-agreement pixels fade rather than asserting a confident colour they have not earned. For a mode-through-time product where support varies enormously with revisit, that is close to a requirement, and it is painful to retrofit once rendering is hard-coded.

Rendering is derived, not authoritative

Because the image is a pure function of the data product plus the mapper, stratum render --run <id> --mapper <ref> reads published data blocks and writes a new image without re-running the pipeline. Colour debates cost seconds. MMGIS can be given a different rendering of the same archival product without forking it. And the mapper version is part of the image’s identity, not the data’s, so restyling does not invalidate the data cache.

Both are recorded in provenance. The iteration path is what the original “custom cost functions as Lambda layers” idea was reaching for; entry points plus a wheel deliver the same ergonomics without the 250 MB layer ceiling.

Everything fails at plan time

Each of these is detected in stage 1, before compute is provisioned:

  • the named plugin resolves, and its version is recordable;
  • required_roles are all present in the manifest’s inputs.roles;
  • required_aux are all declared — an undeclared read is refused, because it produces a cache key that lies;
  • capability and halo are consistent with the configured block size;
  • declared outputs are non-empty, uniquely named, and have a mapper if rendering is requested;
  • filter on_missing policy is explicit.
