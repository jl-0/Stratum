Stratum Pre-release EMIT Critical Minerals L3

Glossary

Every word Stratum uses in a sense of its own, one line each, with a link to where it is explained properly.

Several of these are ordinary words used in a narrow sense — epoch, tile and asset most of all — so read the definition here even when the word looks familiar. Each entry has a stable anchor, so reference/glossary.html#asset is a link you can put in a diagram, a ticket or a slide.

A B C D E G H I L M N O P R S T V W Z

@ref:
A manifest value that names another file, resolved relative to the manifest. Today it is how a categorical layer names its enumeration: classes: "@ref:classes/iron-oxide-v1.yaml". The file's fingerprint enters the manifest hash, so editing the file changes the run. The classes file
Agreement (<layer>_agreement)
For a categorical layer, the winning class's share of the vote: winning epochs over valid epochs, or — with weight: score — the winner's share of the total score, which makes it a confidence. Reported even where the class itself was suppressed. How a cell is decided
Algorithm version (algo hash)
A version stamp that is part of the cache key of anything an algorithm produces — regrid_algo_version for a GLT, warp_algo_version for a warp. Change the algorithm and the key changes, so no stale result can be read back. A recorded content hash catches a change nobody versioned. The recorded regrid hash
AOI (area of interest)
Where a run is. Exactly one of a list of zones, a bounding box or explicit tiles; it resolves to the set of tiles it intersects. Manifest → aoi
Asset
One file that a granule resolves to for one role — the thing a reader actually opens. An EMIT L1B RAD granule has an OBS asset and a RAD asset; an L2B MIN granule has MIN and MINUNCERT. A role names the asset it reads (asset: OBS), and a granule's index record maps each asset to its URL and checksum. A file that no source.patterns glob matches is never indexed or downloaded. A granule is an acquisition, not a file
Asset cache
The directory on one machine where remote assets are staged: verbatim copies of the archive's files, keyed on the catalogue checksum, verified as they download, evicted least-recently-used when the volume runs short of free space. Its location never enters a cache key. Not the same thing as the cache, which holds what Stratum derives. The asset cache
Aux (ancillary source)
Data a plugin reads that is not of the acquisition — a landcover map, a DEM, claim polygons. Declared once under aux: with a URI, a kind and a resampling method, fetched once and warped once per tile, and the same map whichever granule is being scored. If the data is of the overpass, it is a role instead. Roles are granules; aux is everything else
Band alias
A name for one band of a role's variable, so a plugin writes obs["view_zenith"] rather than an index: view_zenith: {role: geometry, band: 2}. Aliases and roles share one namespace. Roles, aliases, and when you need which
best
An aggregation that takes the value from the single highest-scoring epoch, for either kind of layer. The US West geometry bands use it, so all four come from one look. Manifest → aggregate
Block
A square subdivision of a tile, sized in cells by grid.block_size: the unit a worker processes. It never appears in an output, and changing its size cannot change the result. Tile and block
Budget
Required ceilings on a run's fan-out, checked at plan time, before any work item runs. Tiles and granules are enforced; the compute ceiling is declared but not yet estimated. Manifest → budget
Cache
Where every derived artifact lives — GLTs, ortho and aux warps, epoch snapshots, product blocks — under cache/ in the storage root, each at its cache key. It is what makes changing a scorer cheap. Caching & reruns
Cache key (content-addressed)
The hash an artifact is stored under, computed from everything that determines its content: inputs, parameters, plugin versions, algorithm version. A change to any of them is a new key, never an overwrite, so a stale artifact cannot be read by mistake. What invalidates what
Candidate
A granule whose bounding box meets a given block (halo included) and whose acquisition falls in a given epoch, and so might occupy some of its cells. Resolve reads them in (acquisition time, granule id) order, so every tie is decided the same way on every run. The four work lists
Categorical layer
A layer whose values are class ids from an enumeration, such as a mineral id. It is voted or taken from the best epoch, never averaged: the mean of two class ids is a third class nobody identified. Its opposite is a continuous layer. Manifest → layers
Class table
The table that says what a categorical band's integers mean: a key column whose values appear in the pixels, plus attribute columns. EMIT L2B embeds one, 294 rows, at /mineral_metadata. Declared per role, and fingerprinted per granule at plan time. Class tables
Collection
A product line in a catalogue, such as EMITL2BMIN version 001. A role reads from one collection. A granule can span several: L1B RAD and L2B MIN products of the same overpass share a granule id, and the index merges their rows into one record. A granule is an acquisition, not a file
conditional_on
Restricts a continuous aggregation to the epochs whose value in a named categorical layer equals that layer's winner. It is why depth_1 is the band depth of the mineral that won, not an average across epochs that found different minerals. Reducing continuous bands
Continuous layer
A layer of measured quantities — a band depth, an angle, a fraction — aggregated through time by a statistic such as median or score_weighted. Manifest → aggregate
Delivery period
One output product in time, set by time.deliver — for example a year. It is reduced from the epochs in its window, which need not equal the period. Epochs and delivery
Enumeration (classes file)
A product's own list of classes: explicit ids, names, and the input rows each class gathers, matched by attribute rather than by integer. Named by a layer's classes:, usually as an @ref: file; classes: source adopts the input's class table unchanged. Id 0 is reserved for none. The classes file
Epoch
The unit of one vote, set by time.epoch — for example a week. Every observation in an epoch competes per cell and one wins, giving one snapshot, however many overpasses fell in it. That is what stops a densely revisited week outvoting a sparse one. Epochs and delivery
Executor
What runs the work items: local or aws; slurm is specified and not built yet. A command-line choice, never a manifest field, so the same science runs in every place. One pipeline, three executors
GLT (geographic lookup table)
For one granule and one tile, which raw sensor pixel (line, sample) lands in each grid cell, found by nearest neighbour within a max_distance (the default kdtree method). Built once per granule × tile by regrid and cached; its key has no scorer, mask or epoch in it, so every block, every layer and every later run reuses it. Regrid — the geometry
Granule
One acquisition by one instrument — the atom of input. EMIT: about 75 × 75 km at 60 m. A granule is several assets, not one file. A granule is an acquisition, not a file
Granule filter
Which granules may take part at all, decided from index metadata before any pixel is read — cloud fraction, solar zenith, months, build. An ordered list of predicates and plugins. Manifest → granule_filter
Grid
A CRS, a resolution and an origin: a rule for where cell edges fall, with no extent of its own. Tiles and blocks are cut from it. Grid
Halo
A ring of extra pixels a block reads beyond its own edges, for a plugin that needs neighbours. Declared by the plugin, trimmed before writing. Halos
ignore
Classes a vote counts as observed but does not tally — usually [none], so "looked and found nothing" never outvotes a detection. How a cell is decided
Index (granule index)
The table of every granule a run may use — one row per granule per collection, with footprint, time, cloud fraction, build and product versions, and a map of its assets' URLs and checksums — written as parquet by stratum index build from the source. A run reads the index and never the catalogue; the set it selects is frozen and hashed into the run, so a rerun sees the same granules. Building and refreshing the index
Layer
One named band of a snapshot, declared under snapshot.layers: a source, a kind (categorical or continuous), and how it aggregates through time. Every layer is taken from the same winning observation. Manifest → layers
Legend (sidecar)
A published file beside a product that says what its values mean. Each rendered band gets <band>_legend.json — class colours, or ramp stops. The class tables themselves are a separate sidecar: one classes.json when every categorical layer shares an enumeration, otherwise classes.<layer>.json per layer. What a run produces
Lumping
Mapping many input classes onto one product class, as an enumeration declares. It happens as resolve gathers each observation, so a snapshot holds product ids and never the input's raw integers. Why you match on attributes, not integers
Manifest
The one YAML file that defines a run: grid, AOI, time, inputs, filters, masks, scorer, snapshot, outputs, budget. Validated and hashed; the hash is part of the run's identity. Manifest reference
Mapper (OutputMapper)
What turns a product band into a picture — categorical colours, a continuous ramp, transparency from agreement. The data product ships whether or not a band is rendered. OutputMapper
min_count, min_count_unless_score
min_count is how many epochs must agree before a vote's winner is delivered; below it the cell is nodata. min_count_unless_score waives that for a winner holding at least one epoch that scored this high — "one good look is enough; a class seen only through poor looks needs three". How a cell is decided
n_epochs, n_observed
Two count bands every product carries. n_observed is how many epochs any granule reached the cell, before masks and the scorer; n_epochs is how many had a valid winner. The gap between them is what the masks and the scorer removed. Reduce — combining epochs
Nodata
Nothing was observed here. Not the same as none, and a reduction that confuses the two reports confident agreement over pixels nobody looked at. Inside Stratum it is a validity mask; on disk, a sentinel. Missing data
None (class 0)
Observed, and nothing identified. A real answer, unlike nodata; votes usually ignore it so it counts as observed without winning. Missing data
Observation
One granule's contribution to one block: its bands gathered onto the block through the GLT, with masks applied. What a scorer scores. How a block gets its data
Ortho-native
A product delivered already on a map grid, such as EMIT L2B FRCOV. It has no sensor geometry and no GLT, so it is warped onto the block directly — but it is still a per-granule role, not aux. Products already on a map grid
Pixel mask
A rule that makes pixels ineligible — cloud, water, detector edges — before scoring. Masks combine by AND into the observation's valid, and each works in sensor or map space. PixelMask
Plan
Everything decided before a pixel is read: query the index, filter granules, lay out epochs, check the budget, resolve class tables, stage aux, and emit the work lists. What planning decides
Plugin
Science code Stratum calls through a fixed hook — a scorer, pixel mask, reducer, mapper or granule filter — named in the manifest by ref. Readers and sources are plugins too, on the data-access side. The framework knows nothing about minerals; the plugins do. Writing plugins
Product
What a run delivers per tile and delivery period: the reduced data bands, their rendering, legends and a STAC item. What a run produces
Provenance
The record of how a product was made — the frozen index and its hash, asset checksums, class tables, aux digests, algorithm versions, plugin identities, schema hashes and filter counts — written as provenance.json and linked from every STAC item. Reproducing a run
Publish
Stitch a tile's blocks, write the data bands, their rendering, the legends and the STAC item. One work item per tile × delivery period. Publish
Reader
The plugin that opens an asset for a role and returns the requested window of a variable. Chosen per collection; a new file layout needs a new reader, not a change to Stratum. Adding a reader
Reduce, reducer
Collapse the epoch snapshots in a delivery window into one value per cell, layer by layer, using each layer's aggregate. The built-in reducer covers vote, the continuous statistics and best; a reducer plugin is only for what that cannot express. Reduce — combining epochs
Regrid
Build the GLT for one granule × tile. Built once per granule × tile and cached, so changing the science never rebuilds it. Regrid — the geometry
Resolve
For one tile × block × epoch: read each candidate observation, mask it, score it, and keep the best per cell, writing every layer from the winner. The result is the snapshot. Resolve — read, score, keep one
Role
A logical input name — geometry, mineral_1, pv — that the manifest resolves to a collection, an asset and a variable. Plugins name roles, never files or band indices, which is what lets one scorer run on another instrument. Roles and band aliases
Run (run_id)
One execution of one manifest. Its run_id names the runs/ and products/ prefixes in the storage root. Running a mosaic
Runner-up (<layer>_runner_up)
The class that came second in a vote, delivered beside the winner. How a cell is decided
Schema (snapshot schema)
The declared set of snapshot layers — kind, enumeration, aggregation — one per run and constant across its epochs. It can be extended, never redefined. What the snapshot carries
Score
The number a scorer gives one observation at one cell. Highest wins the cell within an epoch; NaN means "may not occupy this cell". The winning score is a band the framework adds to every snapshot, and can weight the vote and continuous aggregations. Scoring and the running best
Scorer
The cost function: the plugin that scores observations, and so decides which look wins each cell within an epoch. The one piece of science every run must name. Scorer
Snapshot (epoch snapshot)
The winning value per cell for one epoch, for every layer, plus three bands the framework adds: the score that won, valid and observed. Written by resolve, cached, and read only by reduce — never rendered. What the snapshot carries
Source (granule source)
Where the index is built from — a catalogue such as NASA CMR, or a directory. Queried when the index is built, never by a run. Where granules come from
source (of a layer)
The role or band alias a snapshot layer is gathered from. Not the same word as the granule source. Manifest → layers
Space (sensor, map)
Which pixel layout an array is in: sensor (downtrack, crosstrack, as the detector saw it) or map (the block grid, after the GLT). A detector-edge mask must work in sensor space; a water mask in map space. Coordinate spaces
Spread
A second band delivered beside a continuous layer saying how much the epochs disagreed — for example iqr, the interquartile range. Manifest → aggregate
STAC item
A JSON document per published tile and delivery period describing its footprint, time, bands, class tables and provenance, so standard tooling can find the products without knowing the storage layout. What a run produces
Stage
One of the five steps of a run, in order: plan, regrid, resolve, reduce, publish. Each stage after plan is a list of independent work items. Lifecycle of a run
Storage root
outputs.bucket: an s3:// URI or a directory, under which cache/, runs/ and products/ all hang, with the same layout either way. Manifest → outputs
Tie break
How a vote picks between classes with equal support: highest_score, earliest, latest, or nodata — the default, which refuses to choose and leaves the cell empty. Mode through time
Tile
A bounded rectangle of the grid, sized in CRS units by grid.tile_size — what a consumer downloads. Named by its grid indices, so a name is a position. Tile and block
valid, observed
Two per-cell flags. valid is true where an observation is eligible — not fill, and admitted by every pixel mask; in a snapshot it means an observation won the cell: reached it, passed every mask and scored. observed is true where any granule reached the cell at all, before masks and the scorer. Missing data
Vintage
Which version of an upstream product a granule is, as its class table reveals. Stratum fingerprints every contributing granule's table and refuses a run that mixes vintages, because the same integer can mean different minerals in two of them. Mixed vintages are refused
Vote
The categorical aggregation: the modal class across the epochs of a window, one vote per epoch — or, with weight: score, each epoch voting with its winning score, so a good look outweighs several poor ones. How a cell is decided
Window
The span of epochs one product is reduced from. By default it equals the delivery period; it can be longer, to make rolling composites. Delivering more often than the window slides
Work item, work list
A work item is the whole input to one worker: one JSON line naming one unit of one stage — a granule × tile for regrid, a tile × block × epoch for resolve, and so on. Plan writes one work list per stage. The four work lists
Zone
A named bounding box in the registry file aoi.registry names (the examples use examples/zones.yaml), which an AOI can name instead of coordinates. Manifest → aoi
