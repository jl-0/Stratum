Why this architecture

Every choice here was forced by something read out of an existing pipeline or a delivered file. This page is the evidence, and what it ruled out.

The reframing that makes everything else possible

V002 and EMIT-AMD use the same GLT machinery in opposite ways. Understanding why is the single most useful thing in the prior art.

V002EMIT-AMD
GLTs per tileone, for all granulesone per granule
Selectionfused into regrid, streaming argmindeferred to a post-apply reduction
Criterion--criteria_band 5 --criteria_mode min (view zenith)none at regrid
MemoryO(grid)O(grid × N)
Temporal integrationimpossible — observations discardedyes, the whole point

They look like different architectures. They are the same one:

The unification

Both are reductions over an observation stack. V002’s reducer happens to be decomposable — a running argmin — so it can be fused into the regrid loop for free. AMD’s is not, so it must materialize. The difference is an optimization, not a design.

Which yields the statement the rest of the system is built on:

Consequence

The GLT is a regrid operator, not the mosaic. Selection is a separate reduction that may or may not be fused into it.

That is what makes temporal aggregation expressible at all, and it is why stage 2 carries no science. It also means both existing behaviours survive as configurations rather than as special cases: a streaming scorer with a single epoch and a no-op reducer reproduces V002 exactly. That parity check is how we know the abstraction is honest rather than merely general.

The seam itself

The entire selection decision in V002 lives in about eight lines of spectral_util/mosaic/mosaic.py:

# obs value at the cell, and what is already there
ob = raw_ob[np.abs(sub_glt[...,1])-1, np.abs(sub_glt[...,0])-1]
existing_crit = criteria[sub_glt_insert_idx[...,0], sub_glt_insert_idx[...,1]]
valid = np.logical_and(sub_glt[...,0] != nodata, ob != local_nodata)

if criteria_mode == "min":
    crit_mask = np.logical_and(ob < existing_crit, valid)
elif criteria_mode == "max":
    crit_mask = np.logical_and(ob > existing_crit, valid)

This is good code. It is also the only place a science team can express a preference, and the vocabulary available to them is one band index and the word min or max. Replacing that comparison with a callable is roughly a fifteen-line change, and it is one of two contributions worth making upstream to SpectralUtil rather than vendoring.

The other is small and consequential: build_obs_nc declares four band names — GLT X, GLT Y, File Index, OBS val — and allocates three. The criteria array is computed and thrown away. For a product whose premise is defensible selection, “why did this pixel win?” must be answerable from the artifact, so Stratum persists the score band.

Wrap, never fork

EMIT-AMD depends on a personal fork of SpectralUtil for a CLI that upstream now ships. That is a trap worth naming explicitly so it is not repeated: contributions go upstream, everything else is built alongside.

Why blocks exist

EMIT-AMD asks Slurm for 32 GB, 4 CPUs and up to 24 hours per 1° bin, because a materialized observation stack over a whole tile is enormous. Ported naively to the cloud that is a large, long, expensive Batch job where one late failure discards everything.

Materialized stack1° tile512×512 block
Cells11.1 M0.26 M
× 100 obs × 10 bands × float32~44 GB~1.0 GB
Observations intersecting the unitalla subset
Fits a 10 GB Lambdanoyes
Blast radius of one failurewhole tile1/42 of a tile

Three things follow. The materialized reduction fits a serverless worker. Parallelism rises roughly 40×, which matters against a 10,000-child Distributed Map. And retries get cheap enough to make Spot instances economically sensible rather than merely cheaper-on-paper.

There is a second, independent argument. write_cog builds the whole output through GDAL’s in-memory MEM driver, plus overviews, before writing — so peak memory scales with tile area regardless of observation count. Blocks attack the term that actually dominates.

Where the original sketch met the service limits

The proposal that started this work sketched AWS Step Functions with Lambda as the main engine and custom cost functions delivered as Lambda layers. Two of those three survive; the reasoning matters because the replacements preserve the intent.

SketchFindingWhat replaced it
Lambda is the main engine Lambda caps at 15 min / 10 GB / 10 GB /tmp. AMD needs 32 GB and hours per tile. A router, not a choice. Block decomposition shrinks the unit until Lambda fits for most work; the planner routes the rest to Batch from measured estimates.
Cost functions are Lambda invocations A per-pixel decision cannot pay an invocation each. It must run in-process, vectorized. In-process plugins resolved by entry point. A wheel fetched from S3 at cold start delivers the ergonomics the layer idea was reaching for — edit, publish, rerun in ~90 s.
Dependencies ship as Lambda layers Zip layers cap at 250 MB unzipped across all layers. GDAL + netCDF4 + scipy + numpy exceeds that before any of our code. Container image Lambdas (10 GB). One image carries both a Lambda entrypoint and a CLI entrypoint, so identical code runs on Lambda, Batch, the cluster and a laptop.
Stateful workflow orchestration Confirmed — Distributed Map reads its work list from S3 and fans out to 10,000 children. Kept as sketched. See Execution.
Terraform generates the infrastructure Confirmed, with a boundary worth naming. Terraform owns the platform; the manifest owns the science. ADR-0002.

What the existing pipelines get right

Most of this design is prior art rearranged, and it is worth being explicit about what is inherited rather than invented.

FromKept
SpectralUtilThe KD-tree regrid itself, the 3-band GLT format, the sign convention marking interpolated cells, and the build_obs_nc guard rails that already refuse a positive y resolution and metres-in-degrees confusion.
EMIT-AMDDeferred reduction. Layered config composition (base ← patch ← patch), which is a genuinely good idea. The stack.mincount / stack.ignore parameters, which are the only working precedent for mode-through-time.
V002Streaming argmin as a first-class execution mode, not a legacy path. Its memory profile — independent of observation count — is worth preserving.
The operatorspipeline.sh’s steps=([query]=1 [apply-glt]=1 ...) switches are hand-rolled caching. Content addressing makes that judgement automatic and correct.
