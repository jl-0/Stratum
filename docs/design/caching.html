Caching & iteration

The property that decides whether people actually iterate on a cost function, or just accept the first one that runs.

The asymmetry

Why this works at all

Stage 2 is expensive and never changes. Stage 3 is cheap and changes hourly. V002 welds them together, so changing a selection criterion rebuilds all the geometry. Separating them deliberately is what turns “try a different cost function” from a full rebuild into a re-read.

The KD-tree query dominates regrid cost — roughly 1.6 M granule points against 11 M grid cells for a 1° tile at 0.0003°. That work depends on the granule, the grid definition and the mask spec. It depends on nothing about the science. So it is computed once and kept.

Scoring, by contrast, is a vectorized pass over a block that is already in memory. It is close to free. The design's job is to make sure that changing the cheap thing does not drag the expensive thing along with it.

Cache keys

Every artifact is written to a key derived from a hash of the inputs that actually determine it — and nothing else. Get that right and two things follow for free: re-running skips completed work, and changing one thing invalidates exactly what depended on it.

Key construction

{cache_prefix}/{artifact_type}/{grid_id}/{tile}/{sha256(canonical_inputs)[:16]}.tif

canonical_inputs is a JSON document with sorted keys, explicit types, and no timestamps or environment-varying paths. It is stored beside the artifact as .inputs.json, so a cache entry can always be explained. That matters the first time two keys unexpectedly differ — and they will.

Rules

RuleFailure mode it prevents
1Only determining inputs go in the key.Extra fields cause spurious misses; a missing one causes silent staleness — much worse
2Version every algorithm. regrid_algo_version is bumped by hand when output changes.A bug fix silently serves stale geometry forever
3Plugin versions are part of the key — wheel path and content hash.A mutable S3 object at a stable URI masquerading as the same plugin
4Aux sources are keyed by content, via ETag or explicit version.A DEM swapped in place under a stable URI — the classic silent-staleness bug
5Undeclared reads are refused.A plugin that quietly opens an undeclared raster produces a cache key that lies
6Cache writes are atomic — temp key, then copy.An interrupted Spot task leaving a truncated artifact that later reads as a hit

Rule 5 is the one that looks like bureaucracy and is not. It is what makes the reproducibility guarantee in invariant 4 mean anything, and it is enforced by the accessor rejecting unknown aliases rather than by trusting plugin authors to remember.

What sharing buys

The GLT cache is keyed on (granule, grid, mask) with no run, project or AOI component. Two consequences, both good:

  • Across experiments. Five competing scorers over one zone share one GLT cache. The first pays for geometry; the rest skip stages 1–2 entirely. Comparing cost functions becomes the cheapest thing the system does — which is precisely the behaviour we want to encourage.
  • Across projects. If AMD and Critical Minerals adopt the same grid, the second project’s first run is nearly free over ground the first has already touched. Deriving tile bounds from the grid rather than from data extents is what makes a GLT byte-identical between them.

Operations

stratum cache stats  --run <id>     # hit rate by type; what a rerun would cost
stratum cache explain <key>         # show .inputs.json and what produced it
stratum cache diff <key-a> <key-b>  # which input differs
stratum cache gc --dry-run          # unreferenced entries past lifecycle

cache diff earns its place. The common confusion is a miss nobody expected, and the answer is always one field in canonical_inputs.

This is already done by hand

pipeline.sh carries steps=([query]=1 [apply-glt]=1 [classify]=1 [stack]=1) so an operator can skip work they believe is still good. That is caching with a human as the invalidation logic. Content addressing makes the same judgement automatic and correct, rather than depending on someone remembering what changed.

And it removes a specific cost: pipeline.sh unconditionally rm -rs glt/ and applied/ on every run, so AMD has no resume at all.

The test that guards this

Non-negotiable from day one

Cache-key sensitivity — a scorer change invalidates snapshots and does not invalidate GLTs. This is the property the entire iteration story rests on, and it is the kind of thing that breaks quietly during a refactor. It is a test, not a convention.
