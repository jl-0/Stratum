Concepts & vocabulary

Three existing pipelines use the same words to mean different things. These definitions are fixed, and the rest of the documentation assumes them.

Vocabulary

TermMeaning here
GranuleOne acquisition from one instrument. The atom of input. EMIT: ~75 × 75 km at 60 m.
GridCRS + resolution + origin. Global and infinite; it defines cell boundaries everywhere.
TileA bounded rectangle of the grid. The unit of product delivery.
BlockA subdivision of a tile. The unit of compute. Never appears in outputs.
EpochOne time window (e.g. a month). Granules within it produce one snapshot.
CadenceThe delivered temporal unit (e.g. a year). One or more epochs reduce into it.
GLTGeographic lookup table. Maps a grid cell → (granule, raw row, raw col).
RoleA logical input name (geometry, mineral, mask) resolved per collection.
ObservationOne granule’s contribution to one block, after regrid and masking.
SnapshotThe winning value per cell for one epoch — output of Scorer.
ProductThe reduced result per tile — output of Reducer, plus its rendering.

Tile is not block

This is the distinction most easily lost, and losing it is expensive.

TileBlock
Decided byProduct design — what a consumer downloadsEngineering — what fits in a worker
Appears inOutput filenames, STAC items, the catalogueNothing user-visible
Changing itChanges the product contractMust change nothing at all
Typical1°512 × 512 cells

Because block size is invisible to consumers, it can be tuned freely against whatever is actually binding — worker memory, halo overhead, per-task fixed cost, retry granularity. That freedom is only real if the invariant below holds, which is why it is enforced by a test rather than by convention.

Invariant

Block-wise output must be bit-identical to tile-wise output. A plugin needing spatial context declares a halo; a plugin needing a global view declares capability = "tile" and gives up block parallelism honestly, rather than corrupting results quietly.

Halos

Block decomposition is only sound for spatially local operations — each output cell depending only on observations over that cell. Mode, median, percentile and count all qualify.

Some things do not, and this is not hypothetical. remove_negatives(clean_contiguous=True) in the existing regrid runs a 3×3 convolve2d over the interpolated-pixel mask and zeroes cells with three or more flagged neighbours. That reads one pixel beyond the block edge, and applied block-wise without overlap it would produce visible seams.

The framework materializes halo extra pixels around each block, runs the plugin, and trims before writing. Cost is (1 + 2h/B)²: at B = 512, a one-pixel halo costs 0.8%, a 32-pixel halo 13%.

Epoch is not cadence

Epochs are the voting population. Cadence is the delivery unit. Monthly epochs reduced to an annual product means twelve votes per output pixel.

Keeping them separate is what makes the temporal question configurable rather than structural. V002 has one epoch and no reduction; EMIT-AMD has many and reduces them. Both are expressible here as manifest settings rather than as different pipelines.

Two rules that were previously unstated anywhere:

  • A granule belongs to the epoch containing its acquisition start, regardless of end time. EMIT granules span roughly 16 seconds, so straddling is not a practical concern — but making the rule explicit costs nothing and removes an ambiguity.
  • Epoch bounds are half-open, [start, end), in UTC. A granule falling outside every epoch is an error at plan time, not a silent drop.

Three coordinate spaces

Confusing these is the most likely source of silent error in the whole system, so every array-bearing type declares which one it is in.

SpaceAxesExtentWhere it appears
sensor(downtrack, crosstrack)1664 × 1242 observedRaw L2B/L1B variables; sensor-space PixelMask
granule-ortho(ortho_y, ortho_x)2363 × 2309 observedThe GLT shipped inside the granule
block(y, x)run-defined, e.g. 512 × 512Everything from stage 3 onward

Cross-track is 1242 columns, which is what the detector-edge trim operates on. And because EMIT is a push-broom — every column is a different detector — masks expressed in sensor space cannot be expressed after regridding has discarded the source column. That is why PixelMask carries a space field rather than assuming map geometry.

Worth knowing

Delivered granules already ship their own GLT at location/glt_x / location/glt_y, mapping the granule’s ortho grid back to sensor space. Its origin is per-granule, so it cannot substitute for the KD-tree regrid onto a shared grid — but it is a ready-made fixture for testing GLT application without first building one.

Fill and nodata

The single most under-specified thing in the design until a real granule was read. It is now settled, and it matters more than it looks.

The rule

-9999 means “no data”. 0 in a mineral ID means “we looked and found nothing”. These must never be conflated.

A reducer that treats them alike will report confident agreement over pixels that were never looked at. EMIT-AMD’s config already distinguishes them — labelling -9999 “fake NaN” and 0 “Tetracorder NaN” — and its stack.ignore: [0, -4] excludes the found-nothing class from voting while still counting the pixel as observed.

QuantityTypeNo-dataMeaning
group_N_mineral_idint16-9999Not processed / outside swath

group_N_band_depthfloat32-9999.0Observed range 0.0–0.5

Internal convention. Once inside Stratum, integer fills are converted to a mask and carried separately; floats use NaN. Sentinels are re-applied only on write. A plugin author therefore sees validity masks, never -9999.

Class tables

Some bands are categorical: their integer values index a table of classes. The framework needs a generic way to carry that table around, and it must not know what the classes mean.

Layering rule

Nothing in stratum core knows about Tetracorder, minerals, spectral libraries or EMIT. It knows that a band may have a class table, that the table has a key column and some attribute columns, and where config says to find it. What those attributes signify lives in stratum_emit.

Delivered L2B granules embed their own class table at /mineral_metadata — 294 entries with columns index, record, name, library, group, url. This is the arrangement to prefer wherever a product offers it, because the authority travels with the data. There is no external CSV to drift, no vintage to pin by hand, and no way for the table to disagree with the pixels it describes. A reader that pulls the table out of the granule it is currently processing is correct by construction.

What remains is a genuine problem, but a tractable one: a mosaic spans many granules, and a pixel value of 15 must mean the same thing in all of them. The index column is positional, and the class list changes between Tetracorder vintages, so a run spanning the reprocessing window can straddle two index spaces.

Because the tables ship with the granules, that is detectable rather than silent: fingerprint every contributing table at plan time, and either proceed, fail loudly, or remap through the attribute columns. Measured on the delivered file, (library, record, group) uniquely resolves 292 of 294 entries — so a remap is computable, with a short list of genuine ambiguities surfaced for a human rather than guessed.

Invariants

These hold across every stage. Violating any of them breaks something else the design depends on, so each is worth stating as a rule rather than a preference.

InvariantWhat breaks without it
1Block size never changes output.Block decomposition silently corrupts any plugin with spatial extent
2Geometry is independent of science. Nothing in stage 2 may read a scorer parameter.The GLT cache stops being reusable, and iteration cost returns to V002 levels
3Every artifact is content-addressed by the inputs that determine it, and only those.Either spurious cache misses, or — far worse — silent staleness
4A run is reproducible from its manifest hash alone.Nobody can explain why two versions of the same tile differ
5Aux data must be declared. Undeclared reads are refused.A plugin produces a cache key that lies about what it read
6Data and rendering both ship. Colour is never the only output.Nothing downstream can restyle, recount, or reprocess — see the AMD counts product
7Categorical classes resolve through attributes, never positional indices.A vintage bump silently reassigns classes with no error anywhere

Two of these are backed by tests that are non-negotiable from the first commit that makes them meaningful: seam equivalence for invariant 1, and cache-key sensitivity for invariants 2 and 3.
