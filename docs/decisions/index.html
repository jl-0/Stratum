Most of these are consistency choices — someone who can build the neighbouring repositories can build this one. Two are load-bearing rather than conventional: GeoParquet + DuckDB, which lets granule selection be frozen and reproduced without a catalogue service; and container images over layers, which is a hard constraint rather than a preference.

Two test fixtures are required

Seam equivalence — block-wise output must be bit-identical to tile-wise. Cache-key sensitivity — a scorer change must invalidate snapshots and must not invalidate GLTs. Both guard properties that fail silently, which is the class of bug a test has to catch because a human will not.

ADR-0002 — The Terraform / manifest boundary proposed

Full record

Terraform owns the platform. The manifest owns the science. Neither owns the code.

The failure mode this avoids: science parameters drift into HCL, and changing a threshold then needs an infrastructure pull request, a plan review and an apply. Since the whole design is optimized so that changing a cost function is cheap, requiring terraform apply to do it would waste the optimization.

Corollaries

  1. A new experiment is a new manifest, not a new deployment. One deployment serves many concurrent runs, distinguished by run_id.
  2. Terraform contains no zone names, no dates, no thresholds, no class names.
  3. Resource sizing is a platform concern; which resource a work item uses is a runtime routing decision from measured properties.
  4. A second deployment is justified only by a real boundary — a separate account for delivered products, or a different region. Never by an experiment.

Enforced by a CI check that greps Terraform for zone names, dates and class identifiers. Crude, but the leak is gradual and a tripwire catches it early.

The honest cost is two configuration systems to learn, plus some ambiguous cases. Is grid.block_size a platform tuning knob or a run parameter? It sits in the manifest because it must be recorded in provenance and may vary per workload — accepting that most users will never touch it.
