Most of these are consistency choices rather than novel ones: a developer who can build SpectralUtil or tetracorder-lite can build this. The two that are genuinely load-bearing are GeoParquet + DuckDB (which is what removes the dependency on a viewer service being up) and container images over layers (which is not a preference — layers physically cannot hold the dependency set).

Two test fixtures are non-negotiable

Seam equivalence — block-wise output bit-identical to tile-wise. Cache-key sensitivity — a scorer change invalidates snapshots and does not invalidate GLTs. They guard invariants that fail silently, which is exactly the class of bug a test has to catch because a human will not.

ADR-0002 — The Terraform / manifest boundary proposed

Full record · 2026-08-28

Decision: Terraform owns the platform. The manifest owns the science. Neither owns the code.

The failure mode being avoided is well documented across data platforms: science parameters leak into HCL, and then changing a cloud-fraction threshold requires an infrastructure pull request, a plan review and an apply. The people the platform exists for stop using it directly, and a platform-team bottleneck forms around parameter changes.

The specific risk here is that the science is expected to change constantly. The whole design is optimized so that changing a cost function is cheap — if that change also requires terraform apply, the optimization is wasted.

Corollaries

  1. A new experiment is a new manifest, not a new deployment. One deployment serves many concurrent runs, distinguished by run_id prefix and execution.
  2. Terraform contains no zone names, no dates, no thresholds, no mineral classes.
  3. Resource sizing is a platform concern, but which resource a work item uses is a runtime routing decision from measured properties.
  4. A second Terraform deployment is justified only by a real boundary — a separate AWS account for delivered products versus experimentation, or a different region — never by an experiment.

Enforced by a CI check that greps Terraform for zone names, dates and mineral identifiers. Crude, but the leak is gradual and a tripwire catches it early.

The honest cost: two configuration systems to learn, and some genuinely ambiguous cases. Is block: 512 a platform tuning knob or a run parameter? It went in the manifest because it must be recorded in provenance and may need to vary per workload — accepting that most users will never touch it.
