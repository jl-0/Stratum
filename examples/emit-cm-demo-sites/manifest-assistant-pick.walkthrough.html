Contender C walkthrough

Written 16 Nov 2026 for review before the CONUS 2023 run. Code references are to Stratum branch review-fixes at b49b385 (not yet merged to main).

Contender C builds a one-year mineral map by picking, for every 60 m grid cell, the single EMIT overpass that best represents the year. It first finds what most overpasses agree the mineral is, in each Tetracorder group separately, then chooses the best-quality overpass among those that show that answer.

In one paragraph

Every overpass ("look") of a cell during the year is masked for cloud, water, built-up land and poor illumination. The surviving looks vote, group 1 and group 2 separately, and the most common mineral in each group is the cell's consensus. Each look also gets a quality penalty from ten metrics, each expressed as the look's rank among that cell's own looks. Looks that show both consensus minerals are ranked by penalty; looks that do not are kept but pushed to the back. The top look wins, and every delivered value for the cell (both mineral ids, both band depths, fractional cover, acquisition time) comes from that one look, so each cell traces to one spectrum.

Grid: the L3 reflectance lattice, EPSG:4326 at 0.00055° (about 61 m), in 0.55° tiles. Time: one epoch covering the whole year, so "the stack" is every look of the year.

Step 1. Which scenes are considered

A scene is dropped whole if its catalogue cloud fraction is above 0.8 or its solar zenith is above 70°. On the demo sites this kept 157 of 465 scenes.

Step 2. Which pixels are usable

A look of a cell is valid only if it passes all four masks and has no fill in any band the ranking reads.

MaskRule
Edge trimDrop the 7 outermost cross-track detector columns each side
L2A standardDrop where any of cloud, cirrus, water, spacecraft or dilated-cloud is flagged
Land coverDrop WorldCover water and built-up
IlluminationDrop where cos(i) is below 0.3
FillDrop where any ranked band is fill. Fractional cover is fill wherever its own QC flags cloud, urban, water or snow.

A masked look neither votes nor can win. This is why roads appear as thin no-data lines: the land-cover mask and the fractional-cover fill both follow them (see open items).

Step 3. The vote

  • Group 1 and group 2 are voted on separately (key: independent). A noisy group-2 answer does not cost group 1 its consensus.
  • Each valid look that detected something in a group casts one vote for that mineral. A look that detected nothing in a group abstains in that group.
  • The mineral with the most votes is the group's mode. A tie between minerals goes to the tied look with the lowest penalty.
  • One agreeing look is enough (min_count: 1).

Step 4. Ranking the looks

Ten metrics, equally weighted. For each metric, each look gets its rank among the cell's valid looks, scaled so the best look is 0 and the worst is 1. Tied looks share the average rank. A cell with one valid look scores 0.

penalty(metric, look) = rank among the cell's n valid looks / (n − 1) P(look) = mean of the ten metric penalties (0 best, 1 worst)

Rank normalisation needs no tuned bounds and behaves the same at a site with 7 scenes as at one with 150. It also means only the order of values matters, so a change of scale in an input (for example fit stored at half scale) does not change the result.

Step 5. The gate and the pick

score(look) = −P if the look shows the group-1 mode AND the group-2 mode = −(P + 10) otherwise (soft gate) winner = the valid look with the highest score; a tie goes to the earliest look

Because P is at most 1, the +10 puts every non-matching look behind every matching one, but still lets one win if no look matches. A hard gate would leave such cells empty.

Properties to understand before scaling

  1. The map shows the winning look's minerals, not the modes. Where no look shows both modes, at least one delivered group is not that group's consensus. The scorer computes the per-group modes (mode_1, mode_2) but C does not deliver them.
  2. agreement is a both-groups measure. It under-reports a cell where one group is unanimous and the other is sparse, and it drives the map's transparency.
  3. Three of the ten ranking metrics describe the mineral, not the look. Band depth, fit and depth uncertainty favour looks whose identified mineral has deep, well-fit features. In C this affects only which look is picked, not the vote (review finding S4).
  4. Band depth averages in a zero for an undetected group. A look that detected only one group has half the depth score of the same look with both.
  5. Fill removes a look from the vote, not only from selection. The external tiled aggregator keeps such a look as a voter, so the two tools can find different modes. Setting the bare weight to 0 restores its voter set.
  6. Adjacent scenes of one pass may count as two looks in a thin strip along scene boundaries (review finding S10, suspected, not measured).
  7. Roads are no-data. Kept by decision on 16 Nov 2026.

Part 2

The implementation

Stratum is a framework plus an EMIT plugin. The framework knows grids, epochs, caching and stages. Everything EMIT-specific (readers, masks, scorers) lives in plugins/stratum-emit and is found by name.

How a manifest name becomes code

The manifest names a plugin with ref:. The plugin package registers that name as a Python entry point in plugins/stratum-emit/pyproject.toml. At plan time the framework looks the name up and instantiates the class with the manifest's params.

manifest-assistant-pick.yaml        scorer: { ref: mode_gated_select, params: {...} }
plugins/stratum-emit/pyproject.toml [project.entry-points."stratum.scorers"]
                                    mode_gated_select = "stratum_emit.scorers:ModeGatedSelect"
src/stratum/plugins.py:28           resolve(kind, ref)  -> the class, via importlib entry_points
src/stratum/plan/run.py:375         instantiate(kind, ref, params) -> ModeGatedSelect(**params)

Masks (stratum.masks) and readers (stratum.readers, keyed by collection short name) resolve the same way. C names no reducer, so the framework's built-in one runs.

Inside resolve: where C's method runs

ModeGatedSelect declares capability = "stack". That tells the framework to hand it all looks at once, not one at a time.

  1. _resolve_stack (resolve/block.py:409) calls read_observation (resolve/observation.py:214) for each scene reaching the block. That reads each role through the GLT, applies the sensor-space masks, then the map-space masks, and sets valid.
  2. The looks are stacked into arrays of shape (N looks, 500, 500) and passed to scorer.score(obs, aux) once.
  3. score returns one score per look per cell. stack_argmax (block.py:391) picks the highest; the earliest look wins a tie.
  4. Every snapshot layer is gathered from the winning look. Scorer diagnostics come from scorer.emit.

What the review changed for this path

  • C's selection logic is unchanged; a test pins its output on the pre-review commit.
  • Cache keys now include the alias-to-band binding, the scene cloud fraction, and a content hash of the plugin and framework code. Changing the mask band or any scorer line now forces a recompute.
  • A worker refuses a plan made under different code, so a stale Lambda image fails loudly.
  • Consequence: after any code change, rebuild the image, re-plan, and expect a cold run.
